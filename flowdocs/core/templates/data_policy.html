1. Purpose and Scope

This Data Policy explains how data within the Sahakar AI platform is classified, stored, retained, backed up, and deleted. It supplements our Privacy Policy and is published in alignment with the data protection obligations under the Digital Personal Data Protection Act, 2023 (DPDP Act) and the Information Technology Act, 2000.

2. Data Classification

Data within the Platform is classified into the following categories:

Service data classifications
CategoryDescriptionExamples
Public Data Government documents that are publicly available and indexed for search by all users. Cooperative society acts, rules, circulars, government resolutions, notifications, and bylaws.
Operational Data Data necessary for the functioning of the Platform, including user account information and system configuration. Admin user accounts (username, email, role, department), system settings, rate-limit counters.
Optional Analytics Data Consent state and pseudonymous, content-free product-analytics information only when the visitor explicitly allows it on an approved host. Signed consent state, opaque browser token, one-way analytics alias, allowed event name and bounded event properties. Search questions, answers, documents, and source URLs are excluded.
Derived Data Data generated through the processing of uploaded documents for search functionality. FAISS vector indexes, text embeddings, chunked document representations, OCR output.
Artifact Data Immutable backup snapshots stored for disaster recovery and data integrity purposes. Generation snapshots containing database dumps, PDF archives, FAISS indexes, and signed manifests.

3. Data Retention Periods

In accordance with the storage-limitation principle under the DPDP Act, data is retained only for as long as necessary for the specified purpose:

Service data retention schedule
Data TypeRetention PeriodNotes
Admin user accounts Until account deletion by an authorized administrator Accounts are deleted only after all associated documents and folders have been transferred or removed.
Public search queries Transient (processed in-memory; not persisted to storage) Queries are not logged to any permanent data store. They exist only for the duration of processing.
Hashed IP addresses 60 seconds (rate-limit window only) Used exclusively for rate-limit enforcement. Hashed inline and discarded when the window expires.
Optional analytics browser records Consent record: 180 days; opaque browser token: 90 days; both can be cleared or reset earlier. Self-hosted analytics event retention is governed by its separately approved operating policy.
Uploaded PDF documents Until removal, deprecation, or archival by an authorized administrator Documents remain indexed and searchable until an administrator explicitly removes, deprecates, or archives them.

Artifact (backup) generations Configurable retention count (default: 7 most recent generations) Older generations beyond the retention count are purged automatically or on demand.
Admin activity and audit logs Rotated per deployment configuration Docker container logs follow the host environment's log rotation policy. Not retained indefinitely.

4. Backup Policy

The Platform maintains a multi-generational backup system through its artifact vault:

  • Generations: Each backup creates an immutable generation containing: SQLite database dump, PDF file archive, FAISS index files, embeddings, and a signed metadata manifest.
  • Storage: Artifacts are stored in an S3-compatible object store (RustFS), isolated from the application network. Vault operations require explicit, authenticated commands.
  • Retention: A configurable number of recent generations is retained. Generations beyond the retention count are purged automatically, removing all associated files and metadata.
  • Validation: Each generation is validated for integrity (checksum verification, PDF count consistency, index coherence) before being marked as available for restore.
  • Promotion: A validated generation can be promoted to active status, superseding the current active dataset.
  • Rollback: Any non-active generation can be restored to a staging environment and promoted to production if needed.
  • Access Control: Vault access is restricted to superadmin-level maintenance operations only.

5. Data Deletion Lifecycle

Data deletion follows a structured lifecycle designed to prevent accidental data loss while ensuring compliance with deletion obligations:

  1. Deprecation: A PDF is marked as deprecated — it is hidden from search results but preserved in the database and existing vault generations. Users can no longer discover the document through search.
  2. Archival: A PDF is marked as archived — it is hidden from both search results and dashboard lists but retained in the database. Archived documents remain restorable.
  3. Deletion: A PDF's file and database record are permanently removed. Note: prior vault generations that include the file are not retroactively purged — they remain as immutable historical snapshots until their generation expires under the retention policy.
  4. Account Deletion: Admin user accounts may be deleted only after all documents and folders owned by the account have been transferred to another authorized user or removed.
  5. Generation Purge: Expired artifact generations are purged from the vault, permanently removing all associated files, database dumps, indexes, and manifests.
  6. Search Query Data: Public search queries are transient and never persisted. No deletion action is required.

6. Data Subject Rights under the DPDP Act

Data Principals (users) may have the following rights under the DPDP Act, subject to applicable law:

  • Right to Access (Section 11): Request confirmation of processing and a summary of personal data held.
  • Right to Correction and Erasure (Section 12): Request correction of inaccurate data or erasure of personal data, subject to legal retention obligations.
  • Right of Grievance Redressal (Section 13): File a grievance with our Grievance Officer regarding any data-related matter.
  • Right to Nominate (Section 14): Nominate an individual to exercise rights on your behalf.

To exercise any of these rights, contact: grievance@ai-sahakar.net.

7. Data Security Measures

Taking account of the DPDP Act and the SPDI Rules where applicable, we maintain reasonable security safeguards including:

  • Encryption of data in transit using HTTPS/TLS.
  • Password storage using salted cryptographic hashing algorithms.
  • Role-based access controls throughout the Platform.
  • Network isolation of internal services from public internet exposure.
  • CSRF protection on all state-changing operations.
  • Session security with HttpOnly and Secure cookie flags.
  • Rate limiting on public endpoints to prevent abuse.
